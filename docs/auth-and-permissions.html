מחזור חיי הסשן

  • Token נשמר ב-localStorage; אין refresh token.
  • כל request עובר דרך authFetch() שמוסיף Authorization: Bearer <token>.
  • 401 → clearSession() + showLoginModal() — המשתמש מתחבר מחדש.
  • SSE endpoints תומכים גם ב-?token= (EventSource לא תומך ב-custom headers).

מנגנון נעילת חשבון

  • 3 קודות שגויות → נעילה ל-10 דקות.
  • נשמר בטבלה locked_accounts (לא ב-memory — שורד restart).
  • נעילה פגה אוטומטית (clean על SELECT); superadmin יכול לשחרר ידנית.
  • גם otp/request בודק נעילה (לא שולח קוד לחשבון נעול).

admin — מגבלות חשובות

  • admin רואה רק משתמשים שהוא יצר (created_by = req.user.sub).
  • clampToAdminPerms: admin לא יכול להעניק הרשאות שאין לו — הפונקציה מחתכת את ה-gantt_ids/category_ids לפי הרשאותיו שלו.
  • admin יכול ליצור viewer/editor בלבד (לא admin אחר).
  • admin לא יכול לערוך/למחוק superadmin.
  • מחיקת admin לא מוחקת משתמשים שיצר — הם נשארים, אך מאבדים את הרשאות ה-gantt/category שלהם (cascade DELETE).

user_all_access

user_all_access הוא טבלה עם שורה אחת לכל משתמש שקיבל גישה מלאה. סמנטיקה: "ראה הכל כולל גאנטים ועתידיים". כשנוצרת קטגוריה חדשה, server.js מוסיף אוטומטית שורה ב-user_category_permissions לכל בעל all_access — כך גם גאנטים עתידיים בקטגוריה זו נגישים.

הענקת all_access מחייבת לנקות את user_gantt_permissions ו-user_category_permissions של אותו משתמש ולהוסיף מחדש. שלילת all_access — אותו הפוך.

hasGanttAccess(user, ganttId, categoryId)

פונקציה פנימית ב-server.js לבדיקת הרשאה לגאנט ספציפי:

function hasGanttAccess(user, ganttId, categoryId) {
  if (user.role === 'superadmin') return true;
  const allAccess = db.prepare(`SELECT 1 FROM user_all_access WHERE user_id=?`).get(user.sub);
  if (allAccess) return true;
  const ganttPerm = db.prepare(`SELECT 1 FROM user_gantt_permissions WHERE user_id=? AND gantt_id=?`).get(user.sub, ganttId);
  const catPerm   = db.prepare(`SELECT 1 FROM user_category_permissions WHERE user_id=? AND category_id=?`).get(user.sub, categoryId);
  return !!(ganttPerm || catPerm);
}
